# SVI ERP — DOCUMENT UNIQUE DE FORME ET DE GESTES

Version du 02/11/2026 (fusion demandée par Ahmed le 01/11/2026, en vocal). **Ce document est le seul qui fait foi** pour l'aspect et les gestes de toute l'application : budget, achats, listes, paramétrage, fenêtres, et toute interface créée plus tard. Il remplace l'ancien FORMAT (`claude/consignes-format.md`) et le document « Prompt codage : uniformisation forme et gestes ». Les règles de calcul et de comportement restent dans le cahier des charges.

**Principe** : un seul document (celui-ci) et un seul endroit dans le code — le **moteur commun** : la base de forme en tête de `styles.css` (variables `--tb-*`, `--blk-*`, `--ttl-*`, `--fold-*`, `--st-*`) et les fichiers communs `09d-couleurs-etats.js`, `09e-gestes-communs.js`, `09e-colonnes-masquees.js`, `09e-mise-en-page.js`, `35-calendrier-saisie.js`. Toute interface, existante ou nouvelle, passe par lui et prend toute seule le format. Pour changer une règle : on change ce document et le moteur, rien d'autre. Une interface qui doit être différente est déclarée dans le **tableau des exceptions** (partie 3) — jamais en cachette dans le code d'une page.

**Principe général (11/10/2026)** : empêcher l'erreur plutôt que la refuser. Une action impossible n'est pas proposée (bouton ou choix grisé, appui long = la raison).

# PARTIE 1 — RÈGLES COMMUNES (toutes les interfaces)

## 1. Palette (PARAMÉTRAGE › FORMAT)
1.1 Une seule interface **PARAMÉTRAGE**, à deux niveaux : des **rubriques** (SOCIÉTÉ, FORMAT, BUDGET, ACHATS…) et des **onglets** dans chaque rubrique (BUDGET : UNITÉS, CHS ; FORMAT : ÉTATS, ÉLÉMENTS, INTERFACES). Le calendrier du budget reste ouvert depuis le budget.
1.2 **Couleurs des états** (modifiables, aucune couleur écrite en dur dans le code) : EN INSTANCE rouge ; FIGÉ vert ; PARTIELLEMENT ACHEVÉ bleu (facture pas entièrement payée, commande pas entièrement reçue…) ; VALIDÉ noir ; EXPIRÉ, BLOQUÉ, ARCHIVÉ (déjà paramétrés, repris).
1.3 **Éléments réglables**, chacun avec : couleur du fond, couleur du texte, taille du texte, gras, italique, souligné (pas de barré) : barre du haut de l'interface ; en-tête de bloc ; rangée d'onglets ; onglet ; onglet actif ; titres des colonnes (en-tête de tableau) ; lignes de titre dans un tableau (ACIER, GROUPE 1…) ; ligne CRÉER ; ligne TOTAL ; bandeau des fenêtres. Valeurs de départ : barre du bloc gris le plus foncé, onglets gris moyen, titres des colonnes gris le plus clair (trois gris neutres) ; lignes de titre gris chaud (jamais le bleu des filtres) ; CRÉER rouge.
1.4 **APPLIQUER À** : un bouton ouvre la liste de toutes les interfaces avec une case chacune et TOUT COCHER ; toutes cochées = la palette vaut partout ; une seule = elle ne vaut que pour cette interface (exception déclarée, partie 3).

## 2. Couleurs et états
2.1 La couleur de l'état vient de la palette. Tout le corps des tableaux dans la couleur de l'état ; titres de colonnes gris.
2.2 **Noir = validé**, partout. DOCUMENTS, TAF et OBSERVATIONS sont validés dès leur saisie : toujours en noir. Vert = figé. Rouge = en instance. Bleu = partiellement achevé.
2.3 **Trait de gauche des blocs** : tous les blocs, SUIVI compris, ont le trait de gauche dans la couleur de l'état de l'écran (palette).
2.4 Une ligne garde la couleur de son propre état (liste des budgets, RÉVISIONS…), pas celle du document ouvert ; même police, même taille, même graisse ; seule la couleur change.
2.5 Liaisons : blanc = non liée ; **un seul bleu clair** = liée (même teinte dans tous les blocs, LOT compris) ; bleu foncé = liée exactement à ce qui est choisi ; rond plein = choisie.
2.6 Cases à cocher et ronds cochés : couleur du mode en cours.
2.7 Compteurs : pastille grise ; quand le nombre n'est pas 0, le chiffre est orange sur une pastille d'un gris plus foncé. Jamais entre parenthèses à l'écran.
2.8 Champs non saisissables : fond gris.

## 3. Barre du haut (en-tête d'interface)
3.1 La même sur tous les écrans, listes comme documents : ≡, référence, i, H, puis à droite ANNULER, RÉTABLIR, PRÉCÉDENT, SUIVANT, ALERTES, FERMER, ⋯. FIGER / VALIDER en tête du ⋯ ; SUPPRIMER en bas du ⋯ à côté de FERMER, séparé par un trait.
3.2 Listes : titre « … (EN INSTANCE) » / « … (VALIDÉS) », compteur, bascule ⇄ au même endroit.
3.3 ⋯ du haut du budget : PRENDRE UNE VERSION et COMPARATIF y sont, accessibles de partout (plus seulement dans le bloc RÉVISIONS).
3.4 Balayage gauche / droite sur la barre du haut = pièce précédente / suivante (achats compris) ; sur un tableau = défilement seulement.

## 4. Blocs
4.1 Même forme partout : barre de titre (icône, nom, compteur, ⋯), onglets éventuels, contenu, poignée de hauteur en bas. Barre de titre basse, ⋯ du bloc plus petit que ceux de la barre du haut.
4.2 AGRANDIR / RÉDUIRE dans le ⋯ ; double toucher sur le titre du bloc = agrandir / réduire. Agrandi = plein écran, mêmes poignées.
4.3 **Hauteur** : par défaut 5 lignes ; réglable à la poignée, gardée où on la lâche ; **mode réduit** = titres des colonnes + UNE ligne entière + la ligne CRÉER (+ TOTAL). Même règle pour chaque onglet (DÉLAIS et RÉVISIONS compris) ; la hauteur du bloc ne change pas d'un onglet à l'autre.
4.4 L'écran ne bouge jamais au redessin ; au retour, chaque bloc reprend son défilement.

## 5. Onglets
5.1 Même forme, même taille, même compteur partout ; tous les onglets d'une rangée de même largeur ; un intitulé trop long passe sur deux lignes.
5.2 **Onglet actif** (palette) : fond, texte, trait dessous dans la couleur de l'état ; il s'arrête net au-dessus des titres de colonnes, sans jamais empiéter sur eux.
5.3 Onglets déplaçables en les glissant, ordre mémorisé ; onglet vide affiché, compteur 0.

## 6. Tableaux
6.1 Titres des colonnes : hauteur, taille et couleur communes (palette) ; jamais coupés ; loupe de tri / filtre sur chaque colonne, éloignée du bord droit ; poignée de largeur posée sur le trait entre deux colonnes ; colonnes déplaçables ; largeur jamais sous le nom (64 px au moins pour une largeur réglée à la main) ; largeurs et ordre mémorisés par tableau.
6.2 **Menu tri / filtre** (comme Google Sheets) : TRIER DE A À Z, TRIER DE Z À A, un trait, FILTRER PAR CONDITION, FILTRER PAR VALEURS (recherche juste au-dessus des cases), EFFACER / OK. Rien ne s'applique avant OK. En-tête bleu quand un filtre ou un tri est actif.
6.3 Lignes de 21 px partout (exception : désignation longue à la ligne).
6.4 **Ronds** à gauche seulement là où il y a des liaisons. **Cases à cocher** à droite partout (supprimer, copier…). Case d'en-tête à trois états (vide, à moitié, plein). Une case cochée filtre les autres blocs seulement quand ils sont liés entre eux (budget : désignations, tâches, produits, charges → TOTAL PARTIEL).
6.5 **Ligne « CRÉER … ICI »** : toujours en rouge (rien n'est validé), même fond et même texte partout, fixée en bas du bloc, juste au-dessus de la ligne TOTAL, jamais derrière ; ne commence qu'à l'alignement des noms. La ligne qu'on crée ou qu'on saisit reste toujours visible et entière.
6.6 **Jamais de ligne vide** ni de « AUCUN » : le compteur 0 du titre suffit, le tableau garde ses titres de colonnes. Pas d'action EFFACER de ligne : une ligne vidée est supprimée.
6.7 **Ligne TOTAL** : total général seulement, en bas, dans les tableaux qui ont des montants ; TOTAL PARTIEL si un filtre ou des cases cochées en cachent.
6.8 **MASQUER / AFFICHER LES COLONNES** : une seule entrée du ⋯, une seule fenêtre au format des tableaux (cochée = affichée) ; au moins une colonne ; choix gardé par tableau (instance / validés séparés) ; aperçu, export et copie suivent l'écran.
6.9 Nombres à droite (1 234,56), unités et ART centrés, tout en MAJUSCULES.

## 7. Pliage, titres et numéros
7.1 Aucun carré autour du signe › / ⌄, même dans l'en-tête.
7.2 Le premier niveau commence sous le nom de la colonne ; chaque niveau rentre du même pas (20 px). Le signe se loge dans une place réservée juste avant le nom, sans le pousser ni sortir de sa colonne : le nom d'un titre et celui d'une ligne simple du même niveau commencent au même endroit.
7.3 LOTS : numéro dans sa colonne, puis le signe (ou sa place vide), puis le nom (« 2 › GROUPE 1 », « 2.1 FONDATION »). Les numéros sont gardés (Gantt).
7.4 **Noms des groupes** : au même niveau, numérotés dans l'ordre de leur création (GROUPE 1, 2, 3…, quelle que soit leur place) ; un groupe créé dedans prend le numéro de son parent (GROUPE 1.1, 1.2) — partout (TÂCHES, PLANNING, PRÉDÉCESSEURS).

## 8. Cases, sélection, clavier
8.1 **Une case = cette case seule** : le cadre épouse exactement le bord de la case (dans LOT / ACTIVITÉS : le nom, sans le numéro ni l'unité), sans vide ; nom décollé de quelques pixels du bord.
8.2 1er toucher = sélectionner (cadre + point rouge), 2e toucher = écrire ; toucher ailleurs = ENTRÉE.
8.3 Plage (Maj + toucher, Maj + flèches, glisser le point rouge) = un seul bloc continu, un seul cadre autour, un seul trait entre les lignes. Ctrl / Cmd + toucher = cases choisies une à une, chacune avec son propre cadre.
8.4 Petit menu des cases : COPIER, COLLER, EFFACER seulement, compact, au format de l'application (jamais la bulle de l'iPad). Au doigt, dans le ⋯ du bloc : ALLER JUSQU'EN BAS, SÉLECTIONNER JUSQU'EN BAS.
8.5 Clavier : flèches = case voisine ; Entrée / Tab = suivante, Maj + Tab = précédente ; Échap = annuler la saisie ; Ctrl / Cmd + C, X, V, Z, Y ; Ctrl + flèche, Début, Fin = aller au bout ; avec Maj = sélectionner jusqu'au bout (comme Google Sheets).
8.6 Saisie : nombre sans zéros inutiles au toucher, chiffres seulement ; texte en majuscules ; jamais de fenêtre Safari ni de bulle iPad ; message d'erreur près de la case, même durée partout.

## 9. Gestes (un seul réglage : `SVI_G`)
9.1 Appui long 450 ms ; glisser à partir de 8 px ; double toucher 350 ms ; même zone de toucher pour tous les petits boutons, ronds et cases.
9.2 Pincement : tableaux (hauteur des lignes, largeur des colonnes), graphiques et Gantt (temps, hauteur ; lignes du Gantt 24 à 80 px).
9.3 Glisser lignes et blocs : appui long, un seul trait ; bleu = même niveau, noir = entre dans un titre ; court = dans la ligne du dessus, long = niveau supérieur ; jaune = superposer.

## 10. Menus ⋯ et fenêtres
10.1 Menus ⋯ : même présentation, groupes séparés par un trait, dans l'ordre : actions propres, MASQUER / AFFICHER LES COLONNES, IMPORTER / EXPORTER / APERÇU, COPIER / COUPER / COLLER, SUPPRIMER (en rouge) / EFFACER LES FILTRES. Un toucher ouvre, un 2e toucher sur le même ⋯ ferme. Toujours entier à l'écran.
10.2 **Fenêtres** : bandeau de titre en haut (couleurs de la palette, comme la barre du haut), ✕ à droite, contenu en vrais tableaux au format commun (titres alignés sur leur contenu, toute la largeur), boutons en bas : ANNULER puis l'action encadrée. Limite de 5 lignes de liste (résumé chiffré au-delà).

## 11. RÉVISIONS (budget)
11.1 Toucher un budget, un scénario, une version ou un recalage = le choisir (l'ouvrir) seulement ; plus de comparatif dans le bloc. Un seul COMPARATIF, commun, dans le ⋯ du haut (scénarios, versions, budgets, autre budget).

## 12. Impression (MISE EN PAGE)
12.1 Aperçu unique MISE EN PAGE ; PORTRAIT / PAYSAGE en premier ; colonnes de départ = celles de l'écran ; MASQUER / AFFICHER propres à l'impression, gardés par type de document.

# PARTIE 2 — RÈGLES PROPRES AUX ÉCRANS (ancien FORMAT, toujours valable sauf où la partie 1 le remplace)

**Points de l'ancien FORMAT remplacés par la partie 1** : 9 (compteurs → 2.7), 11 (états → 2.1-2.2), 13 (bleu → 2.5), 16 (ordre du menu → 6.2), 20 (→ 6.3), 27 (hauteur → 4.3), 28 et 29 (menus → 10.1, 3.1, 3.3), 30 (double toucher → 4.2 ; fenêtres → 10.2), 35 balayage (→ 3.4), 36 onglet actif (→ 5.2), 38-39 (→ 6.4), 43 colonne LOT (→ 7), 49 SAISIR ICI (→ 6.5 : ligne CRÉER partout, SUIVI compris), 67 (barre → 3.1), 70 (→ 2.2), 117 (numéros → 7.3-7.4).

## A. Principes et contrôles
1. **Message d'erreur** : affiché au moment de l'erreur, **près de sa source** (juste sous la case ou la ligne touchée, sans la cacher, au-dessus s'il n'y a pas la place, jamais loin), puis il s'efface seul ; un ✕ à droite du message permet de le fermer tout de suite. Ligne en erreur : le message reste sous la case fautive tant que l'erreur n'est pas corrigée. Cas de refus, saisie et import (règle : cahier, section Saisie et contrôles).

## B. Texte, nombres, dates, compteurs
2. Tout en MAJUSCULES (saisie mise en majuscules), sauf les liens et adresses. Espaces en trop effacés (règle : cahier, section Saisie et contrôles).
3. Corps des tableaux en 12 px, en-têtes plus petits, en gris.
4. Nombres alignés à droite, au format 1 234,56 ; TVA « 20,00 % ». ART et unités (UPB, UCB…) centrés.
5. **Correction d'un nombre** (saisie, toutes les cases numériques) : à la touche, le nombre s'affiche sans zéros inutiles (1,00 → 1 ; 2,50 → 2,5) et tout sélectionné (la frappe remplace) ; en quittant la case, le format revient (1 → 1,00).
6. **Rien de tronqué en « … »** : un en-tête de colonne n'est jamais coupé (la colonne ne peut pas être plus étroite que son intitulé, même si une largeur plus petite avait été mémorisée) ; un intitulé d'onglet trop long passe sur deux lignes (voir 36) ; un tableau d'une seule colonne prend toute la largeur du bloc, moins les 9 px du bord droit (voir 18 ; DÉTAIL QUALITÉ : voir 102). Intitulés en toutes lettres (ACTIVITÉ PRIMAIRE, pas ACT. PRIMAIRE).
7. **Libellés et colonnes des détails** : DÉSIGNATION PRODUIT (détail produits) et DÉSIGNATION CHARGE (détail charges), à l'écran, dans les fenêtres, aperçus et exports ; IMPORT NON CRÉÉ : colonne commune DÉSIGNATION PRODUIT / CHARGE (anciens titres acceptés à l'import : règle : cahier, section Import). Produits : jamais de colonne ART / ARTICLE (écran, aperçus, impressions, exports du détail produits ; fichier du budget : voir 79).
8. Champ, bloc ou onglet obligatoire : une étoile rouge * juste après l'intitulé. Jamais les mentions « OBLIGATOIRE » ni « FACULTATIF », nulle part dans l'app.
9. **Compteurs** (partout dans l'ERP : blocs, onglets, listes, boutons, entrées de menu, CHS, DOC / TAF / OBS…) : à l'écran, toujours dans une pastille grise, jamais entre parenthèses — boutons compris (COCHÉES SEULEMENT, COCHÉES, ✕ DÉLIER, ✕ DÉLIER LES LIGNES COCHÉES, SUPPRIMER LES LIGNES COCHÉES, COPIER / COUPER / COLLER…) ; sans filtre, le total ; avec un filtre actif, « retenues/total » (ex. 12/235). Dans une fenêtre de sélection : pastille grise = lignes disponibles, pastille rouge = lignes retenues. Impressions / aperçus : les nombres de lignes sont entre parenthèses, ex. « LOT (9) ».
10. **Dates** (partout dans l'ERP) : affichage JJ/MM/AAAA À HH:MM dans l'application (écrans, listes, fenêtres) ; JJ/MM/AAAA seul pour une date sans heure (délais). Les dates se choisissent dans un calendrier, pas en tapant JJ/MM/AAAA ; affichage JJ/MM/AAAA après saisie. Le calendrier de FIN ne propose pas de date avant le DÉBUT, et celui de DÉBUT pas de date après la FIN. **Jamais de date qui serait refusée** : dans le calendrier (délais et toute date contrôlée), un jour est grisé dès que sa saisie serait refusée (fin avant le début, jour non travaillé du calendrier du budget (voir 101), fin après la date butoir (voir 87), date qui ne respecte pas une liaison ; règles : cahier, section Planning budgétaire) ; seuls les jours acceptés restent proposés. Une FIN qui dépasse le début d'une tâche suivante n'est pas grisée : elle reste choisissable et ouvre la fenêtre TÂCHES SUIVANTES (voir 64). Exception : les aperçus PDF et les exports gardent la date du modèle de la société, en MAJUSCULES (voir 82) : « AGADIR, LE 14 OCTOBRE 2026 ».

## C. Couleurs et états
11. **Couleur de l'état** : en instance = rouge ; figé = vert ; validé = noir. Tout le corps des tableaux dans la couleur de l'état, en-têtes gris. Listes de budgets : « PROJET BDG AA-MMJJ/NNN » dans la couleur de l'état, sans la mention VALIDÉ / EN INSTANCE.
12. Toutes les cases à cocher et tous les ronds prennent la couleur de l'état (rouge en instance, vert figé, noir sinon), dans tous les onglets et fenêtres ; jamais le bleu du navigateur.
13. **Liaisons, quatre états** : **blanc** = non liée (nulle part) ; **bleu clair** = liée (à n'importe quelle désignation ; comme le choix du budget validé) ; **bleu foncé** = liée exactement à ce qui est choisi (voir 25) ; **bleu + rond à point** = liée à la désignation choisie. Ligne **choisie** : rond plein avec une coche blanche (toujours distinct du rond à point). Ni hachures, ni violet, ni orange.
14. Pas de texte vert de confirmation.
15. **Champs non saisissables** (calculés ou venus d'ailleurs ; origine des valeurs : règle : cahier, section Calculs) : fond gris, partout, même sur une ligne liée ou choisie ; les champs saisissables gardent le fond normal.
    - Désignations client : QPB, MPB HT, MPB TTC gris ; TVA saisissable ; ART calculé affiché en gris (voir 46).
    - Détail charges : PCB, MCB HT, TVA, MCB TTC gris ; une charge absente de CHS garde son PCB saisissable (fond normal).
    - Détail produits : QPB, PPB, MPB HT, TVA, MPB TTC gris ; colonne TÂCHE (LOT › ACTIVITÉ SECONDAIRE) non saisissable ; désignation, unité, NBR, DIM 1 à 3 saisissables ; DIM non autorisées par l'unité grisées (règle : cahier, section Saisie et contrôles).
    - Détail délais : DÉBUT, FIN et DURÉE jamais en gris, même calculées : fond normal, saisissables à tout moment (règle : cahier, section Planning budgétaire). MARGE : gris (calculée).

## D. Tableaux : colonnes, largeurs, lignes, en-têtes (écrans ET fenêtres : import, historique…)
16. **Tri et filtre de colonne** : icône de tri / filtre sur chaque colonne (tri croissant / décroissant, recherche, cases, EFFACER / OK). Comme Google Sheets : rien ne s'applique au tableau avant OK ; ✕ ou toucher ailleurs = rien ne change. La recherche réduit seulement la liste affichée, sans rien cocher ni décocher ; « (TOUT SÉLECTIONNER) » agit sur les valeurs affichées, avec à côté un compteur « cochées/affichées » (ex. 3/24) ; les valeurs cachées par la recherche gardent leur état ; EFFACER retire le filtre de la colonne. Tout le menu du filtre en MAJUSCULES ; bouton OK dans la couleur de l'état (rouge, vert, noir), jamais en bleu. Poignée d'angle (bas gauche) = largeur ET hauteur du menu, mémorisées pour tous les filtres. En-tête de colonne en bleu quand un filtre ou un tri est actif ; les onglets et titres de bloc ne passent pas en bleu pour un filtre (loupe).
17. **Colonnes ajustables et déplaçables** : poignée au bord droit de l'en-tête (zone de réglage plus large au toucher, trait fin, bleu pendant le glissement) ; glisser l'en-tête pour déplacer. Largeurs et ordre mémorisés pour chaque tableau ; l'ordre choisi est gardé à chaque redessin (tableaux de saisie, IMPORT NON CRÉÉ, LIGNES NON LIÉES, LIAISONS VALIDÉES…, pied de tableau aligné) ; COPIER / COUPER, EXPORTER et APERÇU PDF prennent les colonnes dans l'ordre de l'écran. Toutes les colonnes sont réglables, DÉTAIL DÉLAIS compris. Dans les fenêtres PRÉDÉCESSEURS et AJOUTER UNE TÂCHE AU PLANNING : la poignée de l'en-tête LOT règle la largeur des deux volets, celles d'ACTIVITÉ SECONDAIRE, TYPE et DÉCALAGE la largeur des colonnes ; mémorisé pour chaque fenêtre ; le relâchement du doigt ne ferme pas la fenêtre (v428).
18. **Largeur des tableaux** : bloc DÉSIGNATIONS CLIENT : à l'ouverture, toutes les colonnes tiennent dans la largeur du bloc, cases à cocher comprises — la colonne DÉSIGNATION se réduit (pas en dessous de 160 px), sauf si sa largeur a été réglée à la main ; une DÉSIGNATION trop longue passe à la ligne (la ligne devient plus haute). **9 px jusqu'au bord droit** : dans tous les blocs, la dernière colonne s'arrête à 9 px du bord droit du bloc qui la contient (comme ACTIVITÉ SECONDAIRE dans TÂCHES) ; tableau ajusté à la largeur (DÉSIGNATIONS CLIENT) : la DÉSIGNATION rétrécit d'autant ; tableau plus large que le bloc : 9 px en fin de défilement. Le bord gauche n'est pas changé.

IMPORT NON CRÉÉ : défile (trop de colonnes).
20. **Hauteur des lignes** : une seule hauteur (21 px, celle de DÉSIGNATIONS CLIENT) dans tous les tableaux de l'ERP, listes de TÂCHES et fenêtres comprises (PRÉDÉCESSEURS…) ; seule exception : DÉSIGNATION trop longue (voir 18).
21. **En-tête fixé au défilement de la page** : quand un tableau est plus haut que l'écran et que la page défile, l'en-tête des colonnes se fixe juste sous la bande du budget (référence, DOC / TAF / OBS / INF) tant que le tableau est visible ; le titre du bloc (ex. « DÉSIGNATIONS CLIENT 51 » et ⋯) reste collé au-dessus ; fond opaque et légère ombre. Défilement à l'intérieur d'un bloc : en-tête fixé comme avant. Pour tous les blocs, PLANNING compris : en-têtes du tableau ET calendrier (en-tête) du Gantt restent en place, que l'on fasse défiler la page ou le bloc (v440).

Après OK sur un filtre, si cette partie n'existe plus, le bloc se place sur les premières lignes retenues.
23. **Classement par défaut**, croissant : désignations client par ART (ordre naturel 1, 2, 10, 24-A ; ART vide en tête ; même ART → par désignation), à l'intérieur de chaque titre (titres gardés) ; tous les autres tableaux (lots, activités, charges, produits, qualité) par désignation / intitulé. Appliqué à l'ouverture du budget, après un import et après un collage ; ensuite le glisser reste libre (il range aussi la ligne). LIAISONS VALIDÉES : par ART de la désignation puis lot ; LIGNES NON LIÉES : par bloc puis libellé ; IMPORT NON CRÉÉ : voir 76 ; PLANNING : voir 64. Exports et aperçus suivent l'écran. Un tri par en-tête de colonne remplace le classement par défaut tant qu'il est actif.
24. **Ligne saisie rangée aussitôt** (14/10/2026) : une ligne nouvellement saisie (ou modifiée sur une colonne de classement) se range tout de suite à sa place selon le classement par défaut (voir 23), sauf si un tri de colonne est actif.
25. **Ordre des lignes** : 1) lignes choisies (rond plein), 2) lignes liées exactement à ce qui est choisi (bleu foncé ; + rond à point si c'est la désignation qui est choisie), 3) autres lignes qu'on peut choisir : liées (bleu clair) puis non liées (blanc), 4) en bas, les lignes grisées qu'on ne peut pas choisir (voir 56). Désignations et titres : voir 47.
26. **Glisser une ligne** : appui long sur une ligne = glisser la ligne pour la déplacer, dans tous les blocs (le classement par défaut ne vaut qu'au départ, voir 23 ; l'ordre reste ensuite libre). Repère : **un seul trait** à l'endroit du dépôt (voir 44). Superposer pour regrouper (titre ou niveau) seulement dans DÉSIGNATIONS CLIENT et LOTS ; ailleurs, une ligne lâchée sur une autre se place avant ou après elle (15/10/2026). Le défilement reste libre en partant d'une case. Un tri actif empêche de déplacer ou superposer des lignes : un appui long affiche « GLISSEMENT IMPOSSIBLE : TRI ACTIF SUR LA COLONNE X — ANNULER LE TRI POUR DÉPLACER OU SUPERPOSER ».

## E. Blocs, menus ⋯ et fenêtres
27. **Blocs** : hauteur fixe de 5 lignes, même vide ou plus rempli ; ajustable par la poignée, mémorisée. Lots / activités primaires / activités secondaires : trois blocs côte à côte, jamais un seul tableau mélangé ; leur largeur est ajustable par la poignée de leur en-tête, mémorisée. Un élément qui apparaît (bandeau, bouton) ne décale jamais les blocs : sa place est réservée.
28. **Menu ⋯ du bloc** (un seul bouton) : Importer (budget en instance seulement), Exporter, Aperçu PDF, Supprimer les lignes cochées (budget en instance), Agrandir / Réduire ; en instance aussi COPIER / COUPER / COLLER (voir 59) et ✕ DÉLIER LES LIGNES COCHÉES (voir 57) ; compteurs en pastille (voir 9). Bloc vide : EXPORTER et APERÇU PDF sont grisés (l'action n'est pas proposée). Le menu est toujours entièrement dans l'écran — sous le bouton s'il y a la place, sinon au-dessus, sinon sur toute la hauteur de l'écran (il recouvre alors le bouton), sinon sur deux colonnes ; toujours vu en entier, marge de 24 px en haut et en bas (v459). Défilement interne, avec flèche ▼, seulement en tout dernier recours. Mention des lignes cochées dans d'autres onglets : voir 41.
29. **Menu ⋯ en haut du budget** : DUPLIQUER, ↻ DISPOSITION PAR DÉFAUT (grisé quand les blocs sont déjà à leur place d'origine), EXPORTER LE BUDGET (voir 79), IMPORTER UN BUDGET (en instance seulement), ACTUALISER DEPUIS LA SOURCE (en instance, si le budget a été importé, voir 81) ; PLAN D'ASSURANCE QUALITÉ (voir 112).
30. **Double toucher** (15/10/2026, toute l'application) : sur la barre de titre d'un bloc ou sa rangée d'onglets (hors boutons) = agrandir, un nouveau double toucher = réduire (comme ↘↖) ; sur le titre d'une grande fenêtre réglable (PRÉDÉCESSEURS…) = plein écran / taille mémorisée. Jamais sur les en-têtes de colonnes, l'en-tête du Gantt, les lignes ni les petites fenêtres.
    **Format des fenêtres** : format INF / NovApp (y compris toutes les fenêtres de confirmation et de choix) : titre noir, ✕ en haut à droite, libellés à gauche, boutons en bas (ANNULER, puis action encadrée). Jamais de petite fenêtre Safari (saisie, confirmation ou message) : toute question ou confirmation se fait dans une fenêtre de l'application ; un simple message d'information s'affiche dans la fenêtre « INFORMATION » (titre, texte, ✕, FERMER).
31. **Confirmation d'une action qui supprime** : dans la fenêtre même, un titre (nom de l'action), ce qui sera supprimé, boutons ANNULER / action encadrée en rouge. Fenêtres courtes : pas de longue liste à lire ; résumé chiffré (ex. DÉLIER : « 126 LIAISON(S) SERONT DÉLIÉES (51 DÉSIGNATION(S) CLIENT…) »). **Limite de 5 lignes, pour toutes les fenêtres** (confirmation, choix, TITRES VIDES, DOUBLON, DOUBLON EXISTANT, PRODUITS SANS NBR, LIAISON EN COURS NON VALIDÉE, RÈGLE A — LIAISONS À DÉLIER…) : une liste de plus de 5 lignes n'est jamais affichée, un résumé chiffré la remplace ; 5 lignes ou moins : liste affichée.
32. Pas de message de fin d'action (bilan, « terminé », nombre de lignes…) : l'action se fait et la fenêtre se ferme ; le détail va dans l'historique.
33. Fenêtres de choix : seulement le titre et les choix, sans lignes de comptage ni textes explicatifs superflus.
34. Chargement : fenêtre centrale « TÉLÉCHARGEMENT DES DONNÉES… — MERCI DE PATIENTER », écran bloqué.
35. Nouvelle version publiée : bouton « NOUVELLE VERSION — ACTUALISER » en haut, sur tous les écrans (budget en instance compris, vérifié chaque minute), jamais de rechargement automatique.
    **Balayage gauche / droite** (17/10/2026, v455) : il change de budget **seulement dans l'en-tête du budget** (référence, DOC, TAF, OBS, INF), en gardant le bloc agrandi et l'onglet ; dans tous les blocs (tableaux, Gantt compris), il fait seulement défiler, sans jamais changer de budget.

## F. Onglets
36. **Onglets de détail** : le même format partout (instance, figé, validé), dans l'ordre DÉTAIL CHARGES, DÉTAIL PRODUITS * (au moins un produit par liaison, voir 8), DÉTAIL QUALITÉ, DÉTAIL DÉLAIS (+ LIAISONS VALIDÉES, et, seulement s'ils contiennent des lignes, LIGNES NON LIÉES et IMPORT NON CRÉÉ pour un budget en instance). Tous les autres onglets sont affichés, même vides : pas de mise en forme spéciale, le compteur 0 suffit. Intercalaires collés au bloc, avec l'icône, l'intitulé et le compteur (pastille) ; dans chaque bloc, tous ses intercalaires ont la même largeur : par défaut celle du plus long de ses propres intitulés, réduite pour que toute la rangée **et le bouton ⋯** tiennent dans le bloc (un intitulé trop long passe sur deux lignes, jamais « … ») ; une poignée au bord droit d'un onglet règle la largeur de tous les onglets du bloc à la fois, mémorisée ; tous les onglets d'une rangée ont aussi la même hauteur (celle du plus haut) ; le ⋯ reste toujours visible à droite (vaut pour toutes les rangées d'onglets de l'app) ; l'onglet actif a un fond blanc et un trait dessous dans la couleur de l'état.
37. Tous les onglets (détail, DOCUMENTS / TAF / OBSERVATIONS, import, historique…) se déplacent en les glissant, comme les colonnes ; ordre mémorisé.

## G. Cases à cocher, ronds, sélection
38. **Page unique** : rond à gauche de chaque ligne = choix pour la liaison (voir 54) ; case à droite = sélection. Dans un tableau modifiable, la case **coche seulement** (elle ne devient plus 🗑). Cases décochées par défaut. Cases à cocher et ronds d'en-tête et de ligne alignés sur la même colonne.
39. **Case « tout cocher » à trois états** : partout (DÉSIGNATIONS CLIENT, colonnes de TÂCHES, onglets du détail, fenêtres d'import…) — vide si aucune ligne cochée, à moitié (comme un titre) si une partie, cochée si toutes les lignes affichées ; toucher une case à moitié coche tout, un 2e toucher décoche tout. Elle ne coche que les lignes affichées (filtre respecté) et coche aussi les titres. Ligne titre : sa case coche toute sa branche, et passe à moitié (grisée) si une partie seulement est cochée.
40. **Cases cochées et « COCHÉES SEULEMENT »** : cocher une case ne déplace pas la ligne (le tableau garde l'ordre du budget, un seul titre) ; seuls les ronds (choix pour les liaisons) font remonter leurs lignes (voir 25 et 47). Dès qu'une ligne est cochée, un bouton « COCHÉES SEULEMENT » avec son compteur en pastille apparaît (DÉSIGNATIONS CLIENT : à côté du titre ; colonnes de TÂCHES : « COCHÉES » ; DÉTAIL CHARGES / PRODUITS : barre des onglets) : un toucher n'affiche que les lignes cochées (avec leurs titres, total « TOTAL PARTIEL »), un 2e toucher réaffiche tout.
41. **Actions sur les lignes cochées** : SUPPRIMER, EXPORTER, APERÇU PDF, COPIER, COUPER, ✕ DÉLIER sont commandés par le menu ⋯ du bloc (voir 28). SUPPRIMER LES LIGNES COCHÉES est grisé s'il n'y a aucune ligne à supprimer ; confirmation au format de l'application (voir 31). Sur plusieurs blocs (ex. LIGNES NON LIÉES) : le menu et la confirmation détaillent le nombre par bloc (« 47 — 5 CHARGES + 42 PRODUITS »). **Bloc détail, cases cochées dans plusieurs onglets** : SUPPRIMER et ✕ DÉLIER donnent la répartition par onglet dans le menu et dans la confirmation ; une seule mention en haut du menu : « + N COCHÉE(S) DANS D'AUTRES ONGLETS — COPIER, COUPER, EXPORTER ET APERÇU NE PRENNENT QUE L'ONGLET OUVERT ». Lignes prises par chaque action (règle : cahier, section Lignes cochées).

## H. Titres et ART (désignations client)
42. **Ligne titre** : plus de colonne T ; se reconnaît à son signe › / ⌄ ; seules ART et DÉSIGNATION y sont saisissables ; création en superposant deux lignes : voir 44.
43. **Titres repliables** : chaque ligne titre a un signe **›** à côté de son intitulé : toucher = replier (› : lignes et sous-titres cachés partout, même quand des lignes liées montent en haut ; seul le titre reste) ou déplier (⌄). Un sous-titre (I.1) se replie séparément de son titre (I). Au départ tout est déplié ; l'état de chaque titre est mémorisé (dernière utilisation). Une ligne cachée qui devient choisie (rond) ou liée à ce qui est choisi déplie automatiquement son titre. Les exports et impressions / aperçus PDF suivent l'écran (titre replié = titre seulement). Vaut pour tous les tableaux qui ont des titres, et pour les lots du PLANNING (voir 93).
    **Colonne LOT du bloc TÂCHES en arborescence** (15/10/2026) : un niveau par segment du chemin « / », décalé de 16 px par niveau ; signe › / ⌄ devant un niveau qui a des lots dessous (état mémorisé, partagé avec le PLANNING) ; chaque ligne montre seulement le nom de son niveau, modifiable ; un niveau sans lot à lui a son nom modifiable et une case qui coche toute sa branche (pas de rond).
44. **Glissement des lignes et des titres** : appui long puis glisser une ligne ou un titre (un titre emporte toute sa branche, plié ou déplié) ; pendant un glissement, aucune sélection de texte. Repère : **un seul trait** à l'endroit du dépôt, décalé selon le niveau d'arrivée (entre deux lignes d'un même titre, toujours le même trait ; en bas d'un titre : trait décalé = la ligne reste dans le titre, trait aligné sur le titre suivant = elle en sort ; juste sous un titre replié : doigt vers la droite = trait décalé, doigt vers la gauche = trait aligné sur le titre) ; ligne visée encadrée pour superposer ; le nouveau titre créé a son intitulé prêt à être saisi. Fenêtre **TITRES VIDES** (liste des titres, voir 31) : ANNULER / GARDER / SUPPRIMER. Règles de dépôt, de création des titres et effets de TITRES VIDES (règle : cahier, section Titres et ART). Lignes cochées déplacées ensemble : voir 60 ; glissement impossible avec un tri actif : voir 26. Après la dernière ligne d'un titre (v466) : doigt vers la gauche = trait plus long = la ligne sort du titre et prend le niveau supérieur (jusqu'au niveau de la ligne suivante, ou le premier niveau en fin de tableau) ; doigt revenu à droite = reste dans le titre.
45. **Titres en cascade** : chaque niveau de titre décale sa branche de 20 px (≈ 2 à 3 caractères) vers la droite, texte à la ligne compris ; pendant un glissement, le trait d'insertion commence à la DÉSIGNATION, au retrait du niveau d'arrivée (jamais sur ART).
46. **ART calculé** : un ART vide s'affiche en gris avec le numéro calculé (calcul : cahier, section Titres et ART). ART en double (saisi ou calculé, titres compris) : case en rouge, message « ART X DÉJÀ UTILISÉ PAR … » près de la case.
47. **Une ligne n'apparaît jamais seule** : toute désignation est affichée sous son titre (et ses titres parents). Quand une partie seulement des lignes d'un titre remonte (lignes choisies par les ronds, voir 40), le titre s'affiche en haut avec ses lignes remontées et, répété, à sa place au-dessus des lignes restées ; les deux fusionnent quand toutes ou aucune ne sont remontées. C'est le même titre (intitulé, ART, glissement communs).

## I. Saisie et contrôles
48. **Entrée et Tab** = case saisissable suivante, partout dans l'ERP (de gauche à droite, puis ligne suivante ; cases grisées sautées ; Maj + Tab = précédente ; dans une fenêtre, Entrée ne valide jamais toute seule) ; dans IMPORT NON CRÉÉ : case encadrée (fautive) suivante ; ligne corrigée sortie : 1re case fautive de la ligne qui prend sa place. Clavier de l'iPad : touche « Suivant ».
49. **Ligne vide « SAISIR ICI… »** en bas de chaque bloc (sauf DOCUMENTS / TAF / OBSERVATIONS), directement saisissable ; délais : voir 65. **DÉSIGNATION : lecture puis saisie** : la désignation s'affiche en texte (à la ligne si longue, voir 18 ; cascade des titres, voir 45) ; un appui long lance le glissement (déplacer / superposer) sans sélection de texte ; un simple toucher ouvre la saisie au même endroit (Entrée / Tab = case suivante). Descriptif de la désignation : icône i (voir 109).
50. **Unités proposées** : jamais la bulle de Safari ; petite liste au format de l'application sous la case, seulement après la 1re lettre tapée, 6 unités au plus (abréviation + intitulé), toucher = choisir.
51. **Fenêtre DOUBLON** : ouverte par une saisie qui crée un doublon ; elle montre les deux lignes et leur nombre de liaisons ; boutons RÉTABLIR / FUSIONNER ; FUSIONNER grisé avec la raison si la fusion violait la règle A. Doublons déjà présents : voir 52. Définition des doublons et effets des boutons (règle : cahier, section Doublons).
52. **DOUBLON EXISTANT** (à l'ouverture du budget) : une seule fenêtre pour tous les doublons ; sélecteur ‹ i/N › (toucher le numéro = liste des doublons, choix direct) ; IGNORER / FUSIONNER (doublon affiché, puis le suivant) ; IGNORER TOUS (pour la séance) ; FUSIONNER TOUS (confirmation ; ceux que la règle A empêche restent et sont listés à la fin, voir 31) ; ✕ = fermer sans décider (reproposés à la prochaine ouverture).
53. **Fenêtre PRODUITS SANS NBR** (à l'ouverture du budget) : format INF ; produits concernés (liste limitée à 5 lignes, voir 31). Règle (règle : cahier, section Saisie et contrôles).

116. **Toucher ailleurs = ENTRÉE** (17/10/2026, v460) : dans toute l'application, une saisie en cours (ligne SAISIR ICI… ou case modifiée sur place) est validée comme par ENTRÉE dès qu'on touche ailleurs (autre ligne, autre liste, vide, titre), puis ce qui a été touché agit normalement. Un défilement ne valide pas. ✕, FERMER et ANNULER abandonnent la saisie. Une saisie refusée reste dans la case avec son message près de la case (voir 1), et le toucher n'agit pas. Une case vide ne crée rien. **Mise à jour aussitôt (v468)** : dès qu'une saisie est validée (ENTRÉE ou case quittée), le reste du budget suit sans attendre de toucher hors du tableau — autres listes (activité secondaire jumelle comprise), DÉSIGNATIONS CLIENT, onglet de détail ouvert (PLANNING…), compteurs, ⚠ ; seule la liste où l'on saisit garde le clavier (elle se range en quittant le bloc).
121. **Cases de nombre : chiffres seulement, dès la frappe** (v471) : dans toute l'application (QPB, PPB, TVA %, NBR, DIM, DURÉE (J), DÉCALAGE (J), PRÉAVIS, FRÉQUENCE…), une case de nombre n'accepte que les chiffres, une seule virgule (ou un point) — aucune pour un nombre entier (DURÉE, DÉCALAGE, NOMBRE D'OUVRIERS) — et les espaces de séparation ; « − » seulement là où un nombre négatif est permis. Tout autre caractère, tapé ou collé, est retiré aussitôt, avec le message « CHIFFRES SEULEMENT » près de la case (voir 1), sans attendre l'enregistrement. Clavier numérique sur iPad.
122. **Une seule case encadrée à la fois** (v469) : pendant la saisie dans une ligne, seule la case en cours porte le cadre rouge ; le cadre de la case fautive de cette ligne (voir 75) est masqué et revient dès qu'on quitte la ligne (avec son message au toucher).
123. **Colonne U des activités** (v472) : listes ACTIVITÉ SECONDAIRE et ACTIVITÉ PRIMAIRE du bloc TÂCHES, petite colonne U (46 px) avant la case à cocher, en-tête « U ». Activité secondaire : case saisissable (placeholder « U », unités proposées, voir 50), encadrée en rouge tant qu'elle est vide alors que l'intitulé est saisi. Activité primaire : unité de sa jumelle en gris sur fond gris clair, non saisissable. DÉTAIL PRODUITS : UPB d'un produit lié grisée. Manque signalé par ⚠ (ACTIVITÉS SECONDAIRES SANS UNITÉ : toucher = la liste, 1re case vide). Règle : cahier, Unité des activités.
124. **✓ VALIDER grisé d'avance** (v474) : quand la validation serait refusée (règle A, règle D : détail déjà dans la tâche…), le bouton ✓ VALIDER LA LIAISON / LES MODIFICATIONS est gris ; un toucher affiche la raison près du bouton (voir 1, 56) au lieu de tenter la validation.
125. **SAISIE DIRECTE** (v476-v477) : tableau au format des tableaux de l'application (tous les points de ce FORMAT) : en-têtes avec loupe (tri, recherche, filtre), intitulés jamais coupés, largeur des colonnes tirée au bord droit de l'en-tête (mémorisée), sélection d'une colonne par un toucher sur son intitulé (COPIER / COLLER / EFFACER sur les lignes affichées), lignes de 21 px, en-tête fixe et opaque, listes de choix au format de l'application (petite liste sous la case après la 1re lettre, jamais la bulle de Safari), pas de bulle iPad sur une case non active ; fenêtre plein écran, RÉDUIRE / AGRANDIR, taille réglable par le coin (mémorisée), ✕ et ANNULER / VALIDER ; case à cocher en bout de ligne (et case « tout cocher » d'en-tête), bouton ⋯ en haut (SUPPRIMER LES LIGNES COCHÉES avec compteur, TOUT COCHER, TOUT DÉCOCHER, RÉDUIRE / AGRANDIR) ; ligne à supprimer barrée sur fond rouge pâle jusqu'à VALIDER (v479). RÉDUIRE (v481) : la fenêtre devient une petite étiquette bleu foncé en bas à droite (« SAISIE DIRECTE — DÉTAIL CHARGES ▲ ») ; on travaille sur le budget ; un toucher la rouvre telle quelle ; FENÊTRE / PLEIN ÉCRAN pour la taille. Colonne U de l'activité : 46 px, encadrée en rouge tant qu'elle manque, grisée quand elle est imposée. Règle : cahier, SAISIE DIRECTE.
126. **Ligne créée dès la 1re lettre** (v479) : DÉTAIL PRODUITS et DÉTAIL CHARGES (et DÉSIGNATIONS CLIENT) — dès la première lettre tapée dans SAISIR ICI…, la ligne a tout son équipement : rond, case à cocher, cases grises (calculées ou reprises) ; la case en cours garde le clavier. DÉTAIL DÉLAIS non concerné (une ligne par tâche).
127. **SAISIE DIRECTE : un seul ⋯** (v485) : en haut à droite, un seul bouton ⋯ avant ✕, sans boutons séparés (plus de RÉDUIRE, PLEIN ÉCRAN ni COPIER / COLLER / EFFACER dans l'en-tête). Colonne choisie (toucher son intitulé) : l'en-tête affiche « COLONNE « … » SÉLECTIONNÉE : ⋯ » et le menu la propose en premier (COPIER LA COLONNE, COLLER DANS LA COLONNE, EFFACER LA COLONNE), puis un trait ; ensuite COPIER / COUPER LES LIGNES COCHÉES (avec compteur), COLLER LES LIGNES ; un trait ; SUPPRIMER LES LIGNES COCHÉES, TOUT COCHER, TOUT DÉCOCHER ; un trait ; RÉDUIRE, PLEIN ÉCRAN / FENÊTRE. Sous COLLER, une petite ligne grise dit où vont les valeurs. Remplace les boutons du haut du point 125.
128. **COLLER des lignes et d'une colonne** (v485) : dans tous les tableaux de saisie, COLLER accepte un tableau copié dans Excel ou Google Sheets ; les lignes collées arrivent toujours en bas, comme lignes nouvelles, colonne par colonne dans l'ordre de l'écran ; ligne d'en-tête sautée ; colonnes fixes (valeurs en trop ignorées). COLLER DANS LA COLONNE : à partir de la 1re ligne affichée, vers le bas ; une seule valeur remplit toute la colonne ; en SAISIE DIRECTE, les lignes qui manquent sont créées en bas. COLLER toujours proposé (presse-papiers lu au toucher ; la bulle « Coller » de l'iPad peut apparaître). Fin : message bref « N LIGNE(S) AJOUTÉE(S) EN BAS » ; cases refusées listées dans une fenêtre (voir 1).
129. **Ligne rangée par son ART** (v482) : DÉSIGNATIONS CLIENT — dès qu'on quitte la case ART, la ligne prend sa place (sous le titre dont l'ART est le préfixe, avant le premier voisin d'ART plus grand), même en rouge (ART en erreur) ; le tableau est redessiné quand le doigt quitte le bloc (la case en cours garde le clavier).
130. **TOTAL PARTIEL et cases cochées des autres blocs** (v484) : la ligne de total de DÉSIGNATIONS CLIENT, DÉTAIL PRODUITS et DÉTAIL CHARGES devient « TOTAL PARTIEL » dès qu'une case est cochée dans un autre bloc (désignation, lot, activité, produit, charge) ; mise à jour dès le toucher de la case, sans redessiner les autres tableaux.
## J. Liaisons (budget en instance)
54. **Ronds** : 1er toucher = choisir (rond plein, voir 13), 2e toucher = libérer ; seul le rond fait le choix, toucher le texte sert à écrire. Rond d'en-tête de chaque bloc (désignations, lots, activités, produits, charges) : grisé si une ligne du bloc est déjà choisie à la main ; pendant qu'il est actif, les lignes non liées du bloc sont grisées. Logique des choix et du rond d'en-tête (règle : cahier, section Page unique).
55. **Bouton de liaison** en haut à droite (ligne DOC / TAF / OBS), avec une icône i qui ouvre la fenêtre « LIAISON EN COURS » (format INF). Construire et délier passent par ce bouton, qui change selon les choix :
    - rien de choisi : pas de bouton ;
    - **✓ VALIDER LA LIAISON** (vert) : chaîne complète (désignation › lot › act. prm › act. scd) + produits / charges nouveaux ;
    - **✓ VALIDER LES MODIFICATIONS** (vert) : liaison déjà établie avec charges ajoutées ou délais modifiés ;
    - **✕ DÉLIER** (rouge, compteur en pastille) : que des éléments déjà liés, rien de nouveau ; confirmation obligatoire (voir 31) ; liaisons déliées (règle : cahier, section Page unique) ;
    - grisé : rien à valider ni à délier. Mélange de lignes à ajouter et à délier : message passager.
    Fenêtre « LIAISON EN COURS NON VALIDÉE » : ✕, la liste de ce qui serait abandonné (à ajouter, délais modifiés, déliées ; limite de 5 lignes, voir 31), puis ANNULER / ABANDONNER (rouge) / ✓ VALIDER ; quand elle s'ouvre (règle : cahier, section Page unique). On dit « DÉLIER » (jamais « détruire »).
56. **Choix impossibles** : toute ligne qu'on ne peut pas choisir avec les choix déjà faits est **grisée d'avance** et son rond ne réagit pas (gain de temps : l'erreur ne peut plus être commise). **Appui long** sur la ligne grisée : la raison s'affiche près d'elle, puis s'efface. Le grisé se recalcule à chaque choix. Causes (règle : cahier, section Page unique).
57. **✕ DÉLIER LES LIGNES COCHÉES** (compteur en pastille) dans le menu ⋯ des blocs (désignations, lots, activités, produits, charges) et de LIAISONS VALIDÉES (case à droite de chaque liaison) ; grisé à 0 ; confirmation DÉLIER habituelle (voir 31). LIAISONS VALIDÉES : pas de bouton DÉLIER par ligne. Effet (règle : cahier, section Page unique).
58. **LIGNES NON LIÉES** : plus de bouton 🗑 NON LIÉES dans l'en-tête ; les lignes non liées sont dans un onglet **LIGNES NON LIÉES** (compteur en pastille, masqué quand il est vide), au format de LIAISONS VALIDÉES : une ligne par élément non lié, colonnes RÉF. (ART pour désignations et charges, sinon N° de la ligne dans son bloc), BLOC (DÉSIGNATION CLIENT, LOT, ACTIVITÉ PRIMAIRE, ACTIVITÉ SECONDAIRE, PRODUIT, CHARGE) et LIBELLÉ, tri / filtre par colonne ; cases à cocher et SUPPRIMER LES LIGNES COCHÉES par le menu ⋯ du bloc ; COPIER (voir 62). Consultation et suppression seulement (pas de ronds). Toucher une ligne = l'écran va à la ligne dans son bloc, encadrée un instant. Contenu et mise à jour instantanée (règle : cahier, section Page unique), sans faire bouger l'écran (voir 22).

## K. Copier, couper, coller, déplacer
59. **Lignes cochées** : menu ⋯ de chaque bloc (budget en instance) : **COPIER**, **COUPER**, **COLLER** les lignes cochées, avec compteur en pastille (grisé à 0). Lignes coupées en pointillés jusqu'au COLLER. Effets (règle : cahier, section Copier / couper / coller).
60. Appui long sur une ligne **cochée** : toutes les lignes cochées du bloc se déplacent ensemble, dans leur ordre, avec les règles de dépôt habituelles (voir 44).
61. **Sélection d'une colonne** : un simple toucher sur le titre sélectionne la colonne (fond teinté, titre souligné), un 2e toucher la libère ; une seule à la fois ; filtre et glissement du titre inchangés. Menu ⋯ : COPIER LA COLONNE « X » (lignes affichées, ou seulement les cochées), COUPER LA COLONNE, COLLER DANS LA COLONNE. COUPER / COLLER proposés seulement dans les tableaux de saisie en instance (DÉSIGNATIONS CLIENT, DÉTAIL CHARGES, DÉTAIL PRODUITS) et pas sur les colonnes calculées ; ailleurs (TÂCHES, LIAISONS, LIGNES NON LIÉES, IMPORT NON CRÉÉ, DÉLAIS, budget figé / validé) : COPIER LA COLONNE seulement. Sans colonne sélectionnée : COPIER / COUPER / COLLER LES LIGNES COCHÉES sur tout le tableau. Collage dans la colonne (règle : cahier, section Copier / couper / coller).
62. **Onglets de contrôle** (lignes cochées ET affichées) : IMPORT NON CRÉÉ = COPIER, COUPER (confirmé), COLLER (RÉIMPORTER) ; LIGNES NON LIÉES et LIAISONS VALIDÉES = COPIER seulement. Effets (règle : cahier, section Copier / couper / coller).

## L. Totaux
63. **Total général seulement** : ni ligne « TOTAL … » sous un titre, ni montant sur la ligne du titre ; chaque tableau n'a que son total général en bas (écran, exports, aperçus PDF). **Ligne TOTAL à l'écran** — DÉSIGNATIONS CLIENT, DÉTAIL PRODUITS, DÉTAIL CHARGES : libellé « TOTAL » si toutes les lignes sont comptées, « TOTAL PARTIEL » si un filtre en cache ou si des cases sont cochées ; unité et prix affichés quand ils sont communs. Ce que le total additionne (règle : cahier, section Totaux). Aperçus PDF et exports : total normal (présentation : voir 85).

## M. Délais et planning (DÉTAIL DÉLAIS)
64. **PLANNING et calendrier** : DÉTAIL DÉLAIS affiche toujours le PLANNING (une ligne par tâche : LOT, ACTIVITÉ SECONDAIRE, PRÉDÉCESSEURS, DÉBUT, FIN, DURÉE (J), MARGE, JALON ; classement par DÉBUT puis par intitulé ; **DÉBUT, FIN et DURÉE se saisissent directement dans la ligne** (calendrier, voir 10 et 65), enregistrés aussitôt ; tâche choisie par les ronds (ou tâches de l'activité primaire choisie) surlignée en jaune clair, le PLANNING défile jusqu'à elle ; une tâche choisie sans dates y apparaît avec « SAISIR ICI… » (v454 : plus d'écran de saisie d'une seule tâche, plus de récapitulatif, plus de bouton ‹ PLANNING) ; bouton + AJOUTER UNE TÂCHE AU PLANNING ; disposition avec le Gantt : voir 90). Colonnes DURÉE (J) et MARGE centrées. Pas de ligne d'explication au-dessus du PLANNING (voir 33). Ordre des lignes libre (règle : cahier, section Planning budgétaire) : appui long sur une tâche ou sur un lot (avec toutes ses tâches) puis glisser = la / le déplacer ; un seul trait, dont le départ (donc la largeur) suit le niveau d'arrivée, comme les titres (voir 44 ; doigt vers la droite = plus profond) ; un lot lâché dans un titre en fait partie ; lâché au milieu d'un lot simple (ligne encadrée) = niveau « NIVEAU n » qui regroupe les deux ; **tâche lâchée au milieu d'une autre tâche** (ligne encadrée) = fenêtre SUPERPOSER (les deux tâches, LOT et ACTIVITÉ SECONDAIRE modifiables ; CRÉER UN NIVEAU grisé, intitulé en rouge, tant que les deux activités ont le même nom ; raison de la règle A écrite dans la fenêtre ; ANNULER / FUSIONNER / CRÉER UN NIVEAU), puis, s'il y a des produits en double, fenêtre DOUBLONS DE PRODUITS (ANNULER / IGNORER / GARDER LES DOUBLONS) ; sur le Gantt, glisser une barre sans attendre change ses dates sans changer son rang ; appui long sur le milieu de la barre (barre soulevée) puis glisser vers le haut ou le bas change son rang (dans son lot) ; lâchée dans un autre lot (tableau ou Gantt), la tâche change de lot (règle : cahier, section Planning budgétaire) ; activité secondaire du même intitulé déjà dans le lot d'arrivée : fenêtre TÂCHE DÉJÀ DANS LE LOT (format INF) — les deux tâches (lot, DÉBUT, FIN, liaisons), ANNULER / REMPLACER / FUSIONNER ; si la règle A l'empêche, REMPLACER et FUSIONNER grisés et la raison écrite dans la fenêtre (comme DOUBLON, voir 51) ; autres refus : message près de la ligne (voir 1). Case à cocher à droite de chaque ligne (tâche ; lot = toutes ses tâches ; case d'en-tête à trois états, voir 39) ; SUPPRIMER LES LIGNES COCHÉES par le menu ⋯ (confirmation, voir 31 ; règle : cahier, section Planning budgétaire). Noms du lot (ou du niveau de lot) et de l'activité secondaire modifiables directement dans le tableau (toucher le nom = saisie) ; le signe › / ⌄ replie le lot.  PRÉDÉCESSEURS choisis dans la fenêtre LOT / ACTIVITÉ SECONDAIRE (voir 66). Calendrier : dates qui ne respectent pas une liaison et jours non travaillés grisés (voir 10) ; une FIN qui dépasse le début d'une tâche suivante reste choisissable (non grisée). **Fenêtre TÂCHES SUIVANTES** (format INF) : ouverte par une FIN choisie au-delà du début d'une tâche suivante → DÉCALER LES TÂCHES SUIVANTES / ANNULER ; ouverte par une DURÉE modifiée dont la nouvelle FIN sort de la plage permise → RÉDUIRE LA DURÉE / DÉCALER LES TÂCHES SUIVANTES. Règles (liaisons, décalage, durée en jours travaillés) : cahier, section Planning budgétaire. Superposer dans le PLANNING ou sur le Gantt (tâche ou lot lâché sur une autre ligne) : même repère que dans DÉSIGNATIONS CLIENT (voir 44) — ligne visée encadrée d'un trait brun et surlignée en jaune ; sur le Gantt, la ligne de sa barre est aussi surlignée en jaune (v429). **Repère au glissement : le même sur le tableau et sur le Gantt, comme DÉSIGNATIONS CLIENT**, mais seulement du côté où l'on agit — glisser sur le tableau = trait sur le tableau, **aligné sur le titre du lot parent** (lot d'arrivée, colonne LOT) et filant jusqu'au bord droit du tableau ; glisser sur le Gantt = trait sur le Gantt, **aligné sur la date de début du lot parent** (bord gauche de sa barre) et filant jusqu'au bord droit du Gantt ; nom du lot d'arrivée surligné en jaune sur le Gantt pendant le glissement (v445) ; le trait suit le doigt : vers la droite = trait court = dans le lot du dessus, vers la gauche = trait long = lot de niveau supérieur ; vaut pour un lot comme pour une tâche (une tâche reste toujours dans un lot, jamais dans un simple niveau) ; superposition = ligne surlignée en jaune du même côté. L'opération faite d'un côté vaut pour l'autre. **Noms sur le Gantt** : toucher le nom d'un lot (à droite de sa barre) ou d'une activité (dans sa barre ou à droite) = le modifier sur place (même contrôle que dans le tableau ; Entrée / Tab / quitter = enregistrer) ; le signe › / ⌄ replie. **Ligne SAISIR ICI…** en bas du PLANNING : LOT et ACTIVITÉ SECONDAIRE tapés (existants proposés) = nouvelle tâche du planning, puis fenêtre AJOUTER UNE TÂCHE ouverte sur elle, calendrier de DÉBUT ouvert (règle : cahier, section Planning budgétaire). **Niveaux de lot** : la valeur d'un lot rangé dans un autre est son chemin complet (« PH 1ER ETAGE / NIVEAU 4 ») ; CRÉER UN NIVEAU le range dans le lot des deux tâches superposées ; renommer ne change que la dernière partie. Affichage : chemin complet seulement dans les listes de choix ; dans le tableau du PLANNING, nom court décalé en arborescence (comme le bloc LOT) ; sur le Gantt, nom court décalé et marqué ↳ selon le niveau. Lot lâché là où il est déjà : message « … EST DÉJÀ DANS … ». **Niveau nommé automatiquement** (NIVEAU 1.1, NIVEAU 1.1.1…) : affiché précédé du nom de ses parents, en gris, séparés par « / » (« FONDATION / NIVEAU 1.1 »), dans le PLANNING, sur le Gantt et dans la colonne LOT de TÂCHES ; quand la colonne est étroite, le nom des parents se réduit par la gauche, le nom du niveau reste entier ; un intitulé saisi remplace l'affichage (v450).
65. **Saisie des dates** (une seule période par tâche) : dans la ligne de la tâche du PLANNING : DÉBUT, FIN, DURÉE (J) (pas de colonne PÉRIODE). Tâche sans dates : « SAISIR ICI… » dans DÉBUT et dans FIN. Tant qu'une seule valeur est connue, le curseur passe à la date qui manque ; on peut aussi commencer par la DURÉE : elle est gardée, et la date touchée ensuite (DÉBUT ou FIN) calcule l'autre ; dès que la troisième est calculée (règle : cahier, section Planning budgétaire), la saisie est finie (pas de nouvelle ligne). DÉBUT, FIN et DURÉE : fond normal, jamais gris (voir 15).
66. **Fenêtre PRÉDÉCESSEURS / AJOUTER UNE TÂCHE** : taille ajustable (poignée d'angle, mémorisée) ; lots à gauche, activités secondaires à droite (case à droite, case d'en-tête = toutes les activités affichées du lot) ; **bleu = déjà choisi** (lot avec compteur en pastille de ses tâches choisies ; toucher un lot = ses activités) ; lot courant marqué d'un trait ; grisé = impossible (la tâche elle-même ou une boucle) ; pas de liste des choisis en haut ; lignes de 21 px (voir 20) ; tri / filtre sur LOT et ACTIVITÉ SECONDAIRE avec compteur retenues/total. Type et décalage de chaque liaison : fenêtre LIAISON (voir 96). **Fenêtre AJOUTER UNE TÂCHE OU SES DÉLAIS** (16/10/2026 ; bouton « + AJOUTER UNE TÂCHE OU SES DÉLAIS » sous le planning) : on donne ses dates à une tâche du budget, ou on en crée une. Ligne **SAISIR ICI…** en bas des listes LOT et ACTIVITÉ SECONDAIRE (voir 49) : nom tapé + Entrée = ligne créée (ou reprise si le nom existe déjà) et choisie aussitôt ; lot et activité choisis = DÉBUT, FIN, DURÉE (J) ; la première date crée la tâche du planning (sans produit ni charge, non liée, rouge dans TÂCHES ; cahier, Planning budgétaire) ; lot ou activité créé sans date = ligne non liée dans TÂCHES. Lots à gauche, activités secondaires à droite, toutes, au format des blocs LOT / ACTIVITÉ SECONDAIRE (tri / filtre, taille réglable) ; **rouge** = au moins une tâche sans ses deux dates, **noir** = tout daté, **gris** = aucune tâche (une ligne étant choisie de l'autre côté : gris = ne forme pas de tâche avec elle) ; tout reste touchable. Pas de bouton : un lot et une activité choisis ouvrent dans la fenêtre DÉBUT, FIN, DURÉE (J) (calendrier grisé, voir 10), une tâche à la fois, sans intitulé ni état au-dessus des dates (déjà lisibles dans les deux listes) ; une date choisie ouvre le calendrier de l'autre ; les prédécesseurs se règlent sur le planning ; FERMER.

Correction dans l'onglet (Entrée / Tab : voir 48). Effacement : cocher puis SUPPRIMER par le menu ⋯ (confirmation). Contenu, raisons, nouvel essai et doublons (règle : cahier, section Import).

## T. Planning (Gantt, diagrammes, calendrier) — 15/10/2026
(Règles : cahier, section Planning budgétaire.)
90. **Disposition** : PLANNING (tableau) à gauche, Gantt à droite, synchronisés (toute modification d'un côté se voit aussitôt de l'autre) ; jours en abscisse. Le calendrier du Gantt va toujours au moins jusqu'au bord droit visible (tableau caché, poignée tirée, changement d'échelle, rotation) : jamais de zone vide à droite (v458). Entre les deux, un trait vertical avec une poignée ronde (‖) à mi-hauteur : la glisser vers la droite élargit le tableau, vers la gauche élargit le Gantt, de bout en bout (tout à gauche : tableau caché ; tout à droite : Gantt caché) ; position mémorisée pour l'ouverture suivante (15/10/2026). Successeurs en lecture seule dans la fenêtre « i » de la tâche (format INF). À l'ouverture du budget, le tableau montre ses colonnes jusqu'à DURÉE (J) (LOT, ACTIVITÉ SECONDAIRE, PRÉDÉCESSEURS, DÉBUT, FIN, DURÉE), puis la poignée, puis le Gantt ; la largeur choisie à la poignée vaut tant que le budget reste ouvert. La poignée suit le doigt jusqu'au lâcher (zone de prise élargie). Le PLANNING occupe toute la hauteur du bloc (agrandi ou non), au moins deux lignes vides à la fin, tableau et Gantt alignés. **Hauteur des lignes** : deux doigts sur le Gantt écartés à la verticale = lignes et barres plus hautes (24 px au départ = minimum, 64 px au plus, mémorisé) ; à l'horizontale = largeur des jours (voir 91). **Deux doigts = pincement seulement** (agrandir / réduire, en largeur ou en hauteur), bloc agrandi ou non ; ils ne cachent ni ne montrent jamais le tableau. **Poignée** : elle ne réagit que sur sa pastille ‖ (zone de prise élargie autour d'elle) ; le reste du trait est insensible ; tableau caché : marge entre la poignée et le Gantt pour dégager les signes › / ⌄ ; un simple toucher de la pastille = tableau ouvert jusqu'à la colonne DURÉE (J), la glisser = tableau à la largeur où on la lâche (v455). **Poignée toujours stable** : elle ne bouge que si on la touche ou la tire ; à l'ouverture elle se place directement à la bonne largeur (la dernière de ce budget, sinon jusqu'à DURÉE), sans saut ; aucun redessin, import, classement ou pincement ne la déplace ; tableau caché (poignée tout à gauche) : il ne revient que par la poignée — un simple toucher de la pastille l'ouvre jusqu'à DURÉE (v455).
91. **En-tête du Gantt** (mois ou jours) : un toucher ouvre la fenêtre CALENDRIER DU BUDGET (voir 101) sur le mois touché ; ENREGISTRER redessine le Gantt. Affichage JOUR (numéro de chaque jour, jours non travaillés grisés, 14 à 60 px par jour), SEMAINE (« S42 » + date du lundi, 4 à 12 px par jour) ou MOIS (année, puis « OCT. », 1 à 4 px par jour), choisi dans le menu ⋯ (voir 97) ; largeur mémorisée pour chaque affichage ; barres toujours au jour près. Glisser horizontalement sur l'en-tête (ou pincer le Gantt) = élargir / rétrécir les jours (de 14 à 60 px, mémorisé ; le jour sous le doigt reste en place ; largeur affichée pendant le geste) ; un toucher simple (un seul doigt) ouvre toujours le calendrier ; deux doigts ne l'ouvrent jamais (v449). Barre courte (moins de 30 px) : poignées des bouts réduites. **Barres** : fines (environ 11 px) et arrondies aux deux bouts ; une couleur douce par lot, partagée par toutes ses tâches (jamais de rouge, réservé aux tâches critiques) ; nom de la tâche écrit dans la barre quand il y tient en entier, sinon juste à droite (jamais « … ») ; lot déplié : une barre fine (environ 6 px), dans la couleur du lot éclaircie (pour un niveau qui regroupe plusieurs lots : la couleur de son premier lot), une pointe vers le bas à chaque bout, jamais un trait noir ; son nom en gras écrit dans la barre quand il y tient en entier (sur un fond clair de la couleur du lot), sinon juste à droite (v443). Gantt : appui long sans sélection de texte, poignées ni loupe de l'iPad.
92. **Lot replié** : parties travaillées dans la couleur du lot, creux en blanc, reliés par un trait fin en pointillé. Pas de hachures (voir 13). (Tâche en plusieurs périodes : reportée.)
93. **Repli des lots** : signe › / ⌄ devant chaque lot (sur le Gantt, zone de toucher agrandie, v455), comme les titres (voir 43) ; lot replié = une seule barre, de la première date de début à la dernière date de fin ; état mémorisé. Sur le Gantt aussi : signe › / ⌄ à gauche de la barre du lot (ou du niveau), nom à droite ; un toucher sur le signe ou sur le nom = replier / déplier (même état que le tableau).
94. **Tâches critiques** (marge 0) : couleur du lot gardée au centre, dégradé rouge aux deux extrémités (environ 5 à 10 % de la longueur de chaque côté). Colonne MARGE : 0.
95. **Jalon** : étoile ★ dans la colonne JALON et sur la barre. Point d'arrêt qualité sur la barre : voir 107.
96. **Gestes sur le Gantt** : glisser une barre = la déplacer ; attraper son bout = changer la FIN ; appui long sur un bout d'une barre puis glisser jusqu'à une autre (moitié gauche = son début, moitié droite = sa fin ; bout visé marqué d'un point rouge) : fin → début = FIN → DÉBUT ; début → fin = FIN → DÉBUT dans l'autre sens (la barre d'arrivée devient le prédécesseur) ; début → début = DÉBUT → DÉBUT ; fin → fin : pas de liaison ; pendant le glissement, la barre de départ et la barre survolée sont en pointillés (pas de pointillés si la liaison est impossible : la tâche elle-même, une boucle, fin → fin) ; la liaison s'affiche en fil fléché. Glisser sans attendre la barre d'un lot (ou d'un titre) = déplacer toutes ses tâches ensemble (durées gardées, liaisons respectées) ; appui long puis glisser vers le haut ou le bas = changer son rang ou son titre (trait selon le niveau, voir 64). Toucher le fil = fenêtre LIAISON (format INF) : TYPE (FIN → DÉBUT / DÉBUT → DÉBUT), DÉCALAGE (J), 0 par défaut, jamais négatif ; ✕ DÉLIER en rouge, sans confirmation (le fil disparaît ; pas de message de fin, voir 32). Dates impossibles : calendrier grisé (voir 10) ; glissée trop tôt, une barre revient à la première date permise par ses liaisons ; débordement : fenêtre TÂCHES SUIVANTES (voir 64).
